# Day 8 Reflection

The most difficult concept in this course was understanding how to keep data correct when many users make requests at the same time. It was easy to imagine checking whether a seat was available, but I learned that two requests can pass the same check before either one updates the database. I overcame this by connecting the system-design idea to database transactions, row locks, conditional updates, and unique constraints. I also learned that a cache and a waiting room improve performance and traffic flow, but neither can replace the database as the final authority.

For my TicketHub capstone, the strongest part of my design is the explanation of how seat holds, expiry, and payment confirmation work together. My next improvement would be to add a small working prototype or sequence diagram and test two simultaneous requests for the same seat. That would make the concurrency guarantee easier to demonstrate rather than only describe. I have not yet received formal audience feedback, so this improvement is based on my own review; after presenting, I would use the “two stars and a wish” feedback to prioritise the next revision.

Next, I plan to learn Node.js and Express more deeply and build a working REST API backed by PostgreSQL. I will practise input validation, authentication, automated tests, and safe database transactions. I also want to learn how to use load-testing and monitoring tools so I can compare design estimates with measured latency and throughput. This will help me move from writing a design document to building, testing, and explaining a reliable full-stack application.
